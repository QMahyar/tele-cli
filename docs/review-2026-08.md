## MAJOR FINDINGS

### M1. `listen` "reconnect" never reconnects — dead stream loops forever
- **File:** `src/commands/listen.rs:105-131`
- **Issue:** On stream error the code sleeps (backoff capped at 30s) and `continue`s polling the *same* `UpdateStream`. `stream_updates()` is called exactly once. Verified against grammers 0.10: `UpdateStream::next` returns `Err(InvocationError::Dropped)` when the updates channel closes (`grammers-client-0.10.0/src/client/updates.rs:97,223`). With `--timeout-secs 0` this spins forever logging "reconnecting"; with a timeout it wastes the budget. Only 401 terminates.
- **Consensus:** architecture (ARCH-02), testing (REL-04), integration (INT-06)
- **Fix:** On `Dropped`, drop the guard, `connect` + `authorize` + fresh `stream_updates`, with a max-consecutive-failure bound; or terminate with a clean error. Make the log message accurate.

### M2. `listen --timeout-secs` is not honored on idle streams
- **File:** `src/commands/listen.rs:93-106`
- **Issue:** The deadline is only checked at loop top; `stream.next()` is wrapped in a hardcoded `Duration::from_secs(3600)`. On a quiet account `tele listen --timeout-secs 30` (the README quick-start example, README.md:57) can run up to an hour.
- **Fix:** `min(3600, remaining_deadline)` or break on the timeout branch.

### M3. `listen --raw` drops the raw TL payload and bypasses the `--events` allowlist
- **File:** `src/commands/listen.rs:137-139, 199-201`
- **Issue:** `Update::Raw(Raw { raw, state })` is matched as `Update::Raw(_)` and emits `{"event":"Raw","account":…}` only — the raw update is discarded despite the help text promising "output raw TL updates". Raw rows also bypass the `--events` allowlist while parsed rows flow through it (mixed semantics vs cli-contract.md:86).
- **Consensus:** architecture (ARCH-03), integration (INT-05), security (SEC-13)
- **Fix:** Serialize `raw` (and optionally `state`) into the row and apply the allowlist before the raw branch, or remove the feature until implemented.

### M4. `listen` bypasses the `--parallel` clamp — unbounded per-account connections
- **File:** `src/commands/listen.rs:74-79`
- **Issue:** Every other command runs through `run_fanout`'s semaphore (clamped 1–3 per AGENTS.md); `listen` spawns one MTProto connection per account with no limit.
- **Fix:** Acquire a semaphore permit per stream task or clamp via `effective_parallel`.

### M5. `chat admin-log` human table action column always blank (+ latent panic)
- **File:** `src/commands/chat.rs:543-562`
- **Issue:** `admin_action_summary()` returns a JSON *object* (`{"kind":…,"title":…}`), but the human renderer calls `r["action"].as_str().unwrap_or_default()` (chat.rs:557) — `as_str()` on an object is `None`, so the column is always empty. Machine JSON is correct. The truncation fallback `&action[..57]` (chat.rs:559) is dead code today but panics on non-char-boundary the moment the column is fixed naively.
- **Consensus:** architecture (ARCH-01, ARCH-13), testing (REL-01)
- **Fix:** Render `kind`/`title` from the object for the table; truncate with `chars().take(57)`.

### M6. Standard `-100…` channel IDs rejected even when cached
- **File:** `src/entities.rs:43-53, 67-75`
- **Issue:** Users paste full Telegram channel IDs like `-1001234567890`. `raw = id.unsigned_abs()` lands outside grammers-session's `SUPERGROUP_AND_CHANNEL_ID_RANGE` and `MONOFORUM_ID_RANGE`, so both cached and fallback probes return `None` → `INVALID_PEER_ID`, even for a fully cached channel. Test `checked_fallback_ref_rejects_out_of_range_channel` (entities.rs:277) deliberately enshrines the limitation.
- **Consensus:** integration (INT-02), testing (REL-02)
- **Fix:** Try `PeerId::from_bot_api_dialog_id(id)` first, then the existing bare-id probes; add tests for both forms.

### M7. `topic create --emoji` sends the wrong ID type — cannot work
- **File:** `src/commands/topic.rs:152-160`
- **Issue:** `icon_emoji_id` in `messages.createForumTopic` is the ID of the *custom emoji document* (~1e18), not the emoji's UTF-8 bytes. `emoji_to_icon_id` packs 4 bytes into an i64 (😀 → 128512), which the server rejects or ignores. Multi-codepoint emoji (>4 bytes) are silently dropped.
- **Consensus:** integration (INT-03), architecture (ARCH-15)
- **Fix:** Look up the custom-emoji document ID (`messages.searchCustomEmoji` / sticker set lookup), or remove/re-document the flag; validate `--emoji` before invoke (audit H5 remains open).

### M8. QR-login DC migration ignores `dc_id` — hang risk
- **File:** `src/client.rs:120-131`
- **Issue:** `auth.exportLoginToken` can return `loginTokenMigrateTo` with a `dc_id`; the token must be imported on that DC. `qr_login` calls `auth.ImportLoginToken` on the current connection and discards `dc_id`; the server re-issues migration and the `_ => continue` arm loops back to re-export — a plausible infinite loop/hang.
- **Fix:** `client.invoke_in_dc(migrate_to.dc_id, &tl::functions::auth::ImportLoginToken { token: bytes })` (public at grammers net.rs:114).

### M9. `msg forward --silent` reports `forwarded: []` on `updatesCombined`
- **File:** `src/commands/msg.rs:573`
- **Issue:** `messages.forwardMessages` commonly returns `updatesCombined`; `forward_silent` matches only `Updates::Updates`. For other variants `new_ids` stays empty and the CLI prints `forwarded: []` with exit 0 — the forward succeeded but the user is told nothing was forwarded. grammers' own friendly path shares the assumption but panics (loudly); this variant is silent.
- **Fix:** Match `Updates::Updates` and `Updates::Combined`, collect `Update::MessageId`, and error (not empty success) if no IDs extracted.

### M10. Cross-module `TELE_APP_DIR` race makes the unit suite nondeterministic
- **File:** `src/commands/msg.rs:1338,1359,1380,1400` vs `src/commands/takeout.rs:293`
- **Issue:** All unit tests compile into one binary and run in parallel threads. `msg.rs` guards its `std::env::set_var("TELE_APP_DIR", …)` with a private `ENV_LOCK`; `takeout::export_dir_lives_under_app_data_export` mutates the same process-global env var without that lock. A concurrent overwrite/removal can make `app_data_dir()` fall back to the developer's real home config dir → nondeterministic CI failures.
- **Fix:** Inject the app dir as a parameter (functions already take `config_path`), or hoist one process-wide mutex shared by all env-touching tests.

## WHAT IS DONE WELL

- **Machine API discipline:** envelope `{ok, command, dry_run, results}` + exit-code taxonomy locked by 30 offline contract tests; additive-only JSON enforced mechanically, not by convention.
- **Secret hygiene:** api_hash never logged; `Credentials` deliberately has no `Debug`; 2FA stdin-only and never echoed; sessions 0600-in-0700 under app-data dir, never CWD; `.gitignore` covers `.env`/`*.session*`; `tele raw` confined behind a typed registry with honored `--dry-run`.
- **Peer-resolution conventions:** phone-branch strictly before numeric parse, `get_me()` for "me", t.me/telegram.me link normalization, markdown `tg://user?id=` panic guard with edge-case tests.
- **Flood handling:** `error.seconds` propagation, 401→Auth mapping, AutoSleep threshold, `--parallel` clamped 1–3 (except listen).
- **Dry-run discipline:** every mutating command validates and short-circuits before connect, proven by tests (`dry_run_never_touches_network_or_sessions`).
- **Selection logic:** best-tested subsystem — 22 executor unit tests + 9 integration tests covering union/dedup/sort/intersection/clamping.
- **Takeout discipline:** explicit start/export/finish, per-file resume state, private export dir, `TAKEOUT_REQUIRED` handled.
- **Audit follow-through:** 8 of the 2026-08 audit's high/medium findings verifiably fixed (H1, H3, H4-partial, H6, H9, H11, M-U1, plus 23 new tests for previously untested files).
- **CI matches the release contract:** fmt `--check`, clippy `-D warnings`, offline tests on ubuntu + windows.

## METHODOLOGY & LIMITATIONS

- All 5 agents were read-only; no builds, tests, or network calls were run (per AGENTS.md: no Telegram from tests).
- grammers 0.10 claims were verified against the vendored crate source in the local cargo registry, not from memory.
- The agent workflow hit a 30-minute timeout; three agents were resumed to deliver final reports. All scopes completed.
- Static test-count claims (e.g. "268 tests") were cross-checked by attribute counts (~271), not by running `cargo test`.
- Findings are prioritized by cross-agent consensus; items flagged by a single agent were included only when verified against code.

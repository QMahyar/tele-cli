## HIGH/CRITICAL FINDINGS

### H1. `listen --quiet` flag does nothing (BUG)
- **File:** `src/commands/listen.rs:22`
- **Issue:** `ListenArgs` defines its own `quiet: bool` which shadows the global `--quiet`. The local field is never read. `tele listen --quiet` silently fails to suppress logs.
- **Fix:** Remove the local `quiet` field from `ListenArgs`.

### H2. Zero subcommand flags have help text
- **Files:** All `src/commands/*.rs`
- **Issue:** Every `#[arg(long)]` on subcommand structs lacks `help = "..."`. Running `tele msg send --help` shows flags with no explanation of valid formats, accepted values, or behavioral notes.
- **Fix:** Add help text to every subcommand flag.

### H3. `--preview` silently ignored for file uploads
- **File:** `src/commands/msg.rs:~315-325`
- **Issue:** When `--file` is used, `.link_preview(preview)` is never called. The flag exists but does nothing for file sends.
- **Fix:** Either reject `--preview` with `--file` in `validate_send()`, or apply `.link_preview(preview)` to both branches.

### H4. `TeleError::Config` returns wrong exit code
- **File:** `src/error.rs:28-34`
- **Issue:** Config errors return `EXIT_ALL_FAILED` (3) instead of `EXIT_USAGE` (1). No accounts were attempted.
- **Fix:** Add `TeleError::Config(_) => EXIT_USAGE` match arm.

### H5. `topic create --emoji` silently ignores invalid emoji
- **File:** `src/commands/topic.rs:70`
- **Issue:** `emoji_to_icon_id` returns `None` for non-4-byte strings. Topic created without icon, no warning.
- **Fix:** Validate before sending; error if `--emoji` provided but invalid.

### H6. `--schedule` format not documented in help
- **File:** `src/commands/msg.rs:28`
- **Issue:** Accepts Unix timestamps and RFC3339 but only documented in README.
- **Fix:** Add `help = "send time: Unix timestamp or RFC3339 datetime (must be in the future)"`.

### H7. Massive code duplication: `creds()` + `creds_api_id()` × 9 copies
- **Files:** msg.rs, chat.rs, dialog.rs, contact.rs, profile.rs, privacy.rs, takeout.rs, topic.rs, raw.rs
- **Issue:** Identical functions copy-pasted 9 times. Each call re-reads `.env` from disk. For N accounts: 2N redundant disk reads.
- **Fix:** Extract to shared module, load once at startup via `GlobalFlags` or `Arc<Credentials>`.

### H8. Triple `load_config` per command
- **Files:** executor.rs (×2), client.rs (×1 per account)
- **Issue:** `config.toml` parsed 5 times for a 3-account command.
- **Fix:** Load once in `run_fanout`, pass resolved `flood_sleep_threshold` to `ClientGuard::connect`.

### H9. `msg delete --all` loads all message IDs into memory
- **File:** `src/commands/msg.rs:259-263`
- **Issue:** For 500K messages, allocates ~2MB of IDs before deleting any.
- **Fix:** Streaming: fetch 100 → delete 100 → repeat.

### H10. `serialize.rs` has ZERO test coverage
- **File:** `src/serialize.rs`
- **Issue:** All 5 public functions untested. These are the JSON API contract boundary.
- **Fix:** Add unit tests for peer_name, peer_kind, message_to_json, peer_key, media_name.

### H11. No shell completion generation
- **Issue:** Missing `tele completions --shell bash|zsh|fish`.
- **Fix:** Add `clap_complete` dependency and `tele completions` command.
